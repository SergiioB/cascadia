# Inkling expert parallel qualification on alpha, beta and charlie

2026-09-15, branch `feat/inkling-expert-routing`, worktree
`/Users/tatef/Workspaces/tahoma-inkling-ep`. Extends the routing implementation
at `4521e5114b85e95e418acb06625b2c2d3af947de`.

**Three physical NUCs passed distributed correctness and executed real Inkling
experts 2.097× faster on average than the four-CPU local baseline. This is a
resident, single-MoE-layer measurement, not full-model tokens/s.** The complete
tiny-model LAN test also matched every generated token and the logits hash.

The driver ran on **alpha**, using those direct LAN addresses. tate-07 built
the Windows binaries but was not in the measured data path. These measurements
therefore do not include the remote tate-07-to-home-network connection.

Deployment root on each NUC: `C:/Users/tatef/inkling-ep-lan-20260915`.
No existing model files, service configurations, runner installations or SSH
configuration were replaced. No packages were installed on the NUCs. Their
existing `C:/cascadia/fleet/venv/Scripts/python.exe` supplied Python 3.11 and
psutil for the guard.

`tools/inkling_ep_guard.py` runs only an executable inside that root, at below
normal priority, with an explicit CPU affinity and a maximum 600-second lease.
It checks every 0.5 seconds for a CI `Runner.Worker.exe`, active inference
process CPU use, the free-memory reserve and its child's RSS cap. It terminates
only its own child when a limit is reached. It does not pause production jobs.
This is a best-effort interference guard, not a production latency SLA test.

Actual real-weight jobs used CPUs `[0,1,2,3]` and four Rayon threads on each
worker. Alpha's driver used CPUs `[4,5]` and two Rayon threads. The local
baseline used alpha's same `[0,1,2,3]` CPUs and four Rayon threads. Thus the
distributed run uses three memory controllers and twelve compute CPUs;
**the speedup does not isolate memory bandwidth from additional CPU compute**.
The 12 GiB free-memory floor was respected: the lowest sampled available
memory was 14.47 GiB on alpha, 20.09 GiB on beta and 20.54 GiB on charlie.
Real workers peaked at approximately 2.6 GiB RSS each; the local oracle used
7.66 GiB. RSS is sampled, not an exact lifetime maximum.

OVMS live/ready endpoints on port 9000 returned HTTP 200 before and after.
Protected process PIDs and creation times matched through the jobs and final
audit. At completion, all task workers exited, TCP 29473 had no listener, and
the task's firewall rules were removed. The original inference and CI services
were left running. Isolated files remain for the next experiment.

## Exactly what ran

1. **Complete tiny model over three machines.** The checked-in four-layer,
   hidden-size-64 fixture used a driver without MoE bins and workers containing
   only their assigned expert bins. Two eight-token greedy generations matched
   the local baseline's tokens and logits hash `1f7cd0eb14a22662`. The fixture
   benchmark explicitly uses `--allow-fixture`; it is not a 975B measurement.
2. **Real 975B export expert phase, layer 2 only.** Original packed int4 expert
   bins came from `miner:/mnt/external_ssd/inkling/out/experts/layer_02`.
   Each is 31,850,496 bytes. The layer has 256 routed plus two shared experts,
   totaling 8,217,427,968 bytes. SHA256 was verified during every transfer.
   Alpha retained the entire layer for the local oracle; beta and charlie each
   retained 87 assigned bins (2,770,993,152 bytes). Alpha's remote worker loaded
   only its assigned 88 bins. Shared experts were replicated across workers.
3. `inkling_ep_layer_bench` uses 36 route frames: first 12 decode positions of
   repetition zero for each of the CPU record's three prompts, at layer 2,
   with shared IDs 256 and 257 appended. Routes come from
   `tools/inkling_autolab/results/129-second-prefetch-confirmation-routes.json.gz`.
   **Inputs are synthetic**, generated by the saved per-frame LCG seed; each
   selected expert has weight 1/8. Router scores and hidden states are not
   replayed from the real generation. The source defines the exact generator.
4. The partial manifest keeps real hidden size 6144 and MoE intermediate 3072,
   but declares only layers 0–2, with 0 and 1 marked dense. The phase probe
   loads only MoE bins. No attention, embedding, head, dense MLP, prefill or
   token generation executes in this phase test.
5. `CASCADIA_INKLING_EP_OWN_EXPERTS=1` copies assigned packed bins into worker
   memory at startup. Both configurations perform one complete warm pass and
   three timed repetitions: **108 evaluations each**, each selecting six
   routed and two shared experts. Loading and warm-up are excluded.
6. The local warm pass writes all 36 output vectors to `layer-reference.bin`.
   The remote warm pass must match every byte of that reference. Every timed
   output then must equal its corresponding warm output byte for byte.
   The retained reference's checksum is in `reference-sha256.json`.

This is a **CPU expert backend** test, with no GPU kernels or new exports.
The workers were built with the release MSVC toolchain on tate-07, Rust 1.98.1;
see `build-provenance.json` for compiler, fingerprint flags and build log.
The native source checksum and all three binary SHA256 values are saved.

## Measured results

| Time per expert-phase evaluation | Alpha local | Three NUCs, including dispatch/gather |
|---|---:|---:|
| Mean | 13.72184 ms | 6.54454 ms |
| Median | 13.71760 ms | 6.18910 ms |
| p95 | 13.84860 ms | 7.92020 ms |
| Maximum | 14.23190 ms | 8.41480 ms |

Mean ratio: **2.09669×**. Median ratio: 2.21641×. Percentiles use nearest rank,
except the median which averages the central pair. This is one bounded local /
distributed comparison, not a confidence interval or an all-layer prediction.
The placement uses illustrative cost coefficients (`read_us=100`,
`compute_us=10`, `dispatch_us=200`); they were not fitted to this sample.

Transport probes use the actual expert protocol and the same connections,
with one padded slot that returns zeros without reading weights. Payload is
24,576 bytes each way, plus framing. Each endpoint gets 34 round trips; the
first two are discarded. These are application round trips, not ICMP ping.

| Worker | Median round trip | Maximum of 32 retained observations |
|---|---:|---:|
| alpha (same host as driver) | 0.28075 ms | 0.33050 ms |
| beta | 0.36895 ms | 0.75830 ms |
| charlie | 0.44340 ms | 0.84060 ms |

The three NUCs provide about 95 GiB total physical memory before existing
services and OS reserves. The complete packed model is roughly 549 GB, so
**this group cannot hold the entire model resident**. A full-model experiment
needs additional weight capacity or a measured paging/cache/fallback design.
This 2.10× phase result does not establish a new full-model tok/s record,
25 tok/s, or the same speedup over the previously tuned single-box runtime.

## Reproduce and continue

The saved artifacts are in [inkling-ep-lan](inkling-ep-lan/). `summary.json` is
derived from raw timings, fixture results and final service audits:

```sh
python3 tools/inkling_ep_lan_report.py \
  --artifacts docs/perf/inkling-ep-lan --out /tmp/inkling-lan-summary.json
```

Access credentials remain in `~/.secrets`; do not copy their contents into
scripts or logs. `tools/inkling_ep_lan_control.py` uses `nuc_ssh_config` and
the existing password helper with per-command hostname overrides. It supports
`put HOST ZIP`, `exec HOST LOCAL_PYTHON_SCRIPT`, `job HOST LOCAL_JOB_JSON`, and
`get HOST REMOTE_RELATIVE_PATH LOCAL_DESTINATION`. Bundles extract only into
the marked isolated root. It does not edit the shared SSH configuration.

For new binaries, run `tools/inkling_ep_build_windows.bat` in an isolated
Windows checkout with Visual Studio Build Tools. Package its three `.exe`
files under `bin/`, plus the guard, inputs and placement. The tested files
remain under `C:/Users/devcloud/inkling-ep-20260915/target/release/examples` on
tate-07 and under `bin/` on the NUCs. The source/export need not be rebuilt for
the exact saved jobs.

To rerun against the already staged shards:

- Recheck addresses, idle CI/inference, free memory/disk and executable hashes.
  Keep the resource limits. Each host's `*.job.json` in the artifacts contains
  the exact argument list, environment, affinity and limits used here.
- Copy those job definitions to new local files with **new labels and output
  paths**. Outputs and job logs use create-new semantics; do not overwrite the
  evidence. Run alpha's local job first to create a new reference.
- Temporarily allow inbound TCP 29473 only for the isolated worker executable
  and source address `192.168.0.101`. Rule name used here was
  `InklingEP-LAN-20260915`. Leave existing rules and services alone.
- Launch one guarded worker job on each host concurrently. Wait for
  `bank_loaded` and `listening=` in each task log. Do not make a test connection:
  these workers accept one driver connection and exit when it closes.
- Launch the guarded alpha driver with endpoints, in order,
  `192.168.0.101:29473,192.168.0.103:29473,192.168.0.188:29473`. It must use the
  same placement and new local reference. Read final guard statuses; a guard
  preemption is an incomplete run, not a timing result.
- Collect output and status JSONs, confirm the original services remain healthy,
  and remove only the temporary task firewall rule on each host. Worker leases
  bound orphaned waits; do not leave a benchmark daemon running indefinitely.

For fresh staging, `inkling_ep_source.py` serves only the explicit layer's
expert filenames and SHA256 index for a bounded lease. We bound it to miner's
`192.168.0.235:29483`, with only the three NUC source IPs allowed, and temporarily
added matching source-specific UFW rules. `inkling_ep_stage_layer.py` used
48 MiB/s per host, below-normal process priority, an 80 GiB free-disk floor and
CI checks between files. Alpha's 8.217 GB transfer took 163.266 seconds; beta
and charlie's 2.771 GB transfers took 55.062 and 55.141 seconds. The source
process and all three temporary UFW rules were removed after staging.

Two setup failures are retained in logs: the initial fixture omitted its
explicit fixture flag and refused to run; the first transfer attempts timed
out on the miner's firewall. Both were corrected before measurements. Native
builds, LAN fixture parity, real-expert parity and the artifact validator passed.
Clippy completed with existing library warnings and no warnings in the new
example; `-D warnings` is blocked by existing warnings in the OV shim. Python
helpers pass `py_compile`. These checks do not qualify GPU expert numerics or
fault-tolerant/live multi-driver service operation.
